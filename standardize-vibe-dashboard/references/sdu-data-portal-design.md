# SDU Data Portal Design System

Use this reference when building or reviewing React dashboards generated by this skill. The goal is a consistent SDU Data Portal product surface, not a generic landing page.

## Theme

The UI is light by default and must support a complete dark theme. Store the selected theme in `localStorage` and apply it through `[data-theme="dark"]`, `html.dark`, or the equivalent already used by the app.

Use these CSS variables as the core contract:

```css
:root {
  --bg-color: #f8f9fa;
  --card-bg: #ffffff;
  --primary-blue: #2563eb;
  --secondary-blue: #1d4ed8;
  --accent-blue: #3b82f6;
  --text-main: #1a1a1b;
  --text-muted: #64748b;
  --glass-border: rgba(0, 0, 0, 0.08);
  --pill-radius: 100px;
  --card-radius: 21px;
  --shadow: 0 10px 30px -10px rgba(0, 0, 0, 0.1);
  --transition: all 0.4s cubic-bezier(0.23, 1, 0.32, 1);
  --font-family: Inter, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
}

[data-theme="dark"],
.dark {
  --bg-color: #0a0a0a;
  --card-bg: #141414;
  --primary-blue: #3b82f6;
  --secondary-blue: #2563eb;
  --accent-blue: #60a5fa;
  --text-main: #ffffff;
  --text-muted: #888888;
  --glass-border: rgba(255, 255, 255, 0.08);
}
```

If the reference CSS contains `--accent-yellow`, replace it with `var(--primary-blue)` unless the SDU team defines a real yellow token.

## Color Roles

- Primary action and focus: `--primary-blue`
- Primary hover: `--secondary-blue`
- Secondary chart accent: `--accent-blue`
- Page background: `--bg-color`
- Surfaces: `--card-bg`
- Text: `--text-main`; metadata and captions: `--text-muted`
- Borders and dividers: `--glass-border`

Semantic dashboard colors:

- Success / low risk: `#22c55e`
- Warning: `#f59e0b`
- Error / high risk: `#ef4444`
- Chart neutrals: `#E5E7EB`, `#6B7280`, `#9ca3af`, `#1f2937`

Do not introduce a second strong brand color unless the user explicitly gives a product reason.

## Typography

- Use Inter for all UI text. In closed networks, bundle or self-host Inter instead of depending on Google Fonts at runtime.
- Body text: `1rem`, weight `400`-`500`, line-height around `1.6`.
- Section headings: `1.8rem`-`2rem`, weight `700`.
- Card headings: `1.4rem`-`1.8rem`, weight `700`.
- Navigation: `0.9rem`, weight `500`.
- Logo wordmark: `1.2rem`, weight `800`.
- Big dashboard numbers: `3.5rem`-`4rem` on spacious layouts, weight `800`, with `font-feature-settings: "tnum"` when values update or align in grids.
- Very large `5rem / 800 / letter-spacing -3px` headings are not a default dashboard pattern. Dense dashboards should use compact headings.

## Components

### Buttons

Primary buttons:

- Background `var(--primary-blue)`, white text.
- Pill radius `var(--pill-radius)`.
- Typical padding: `0.6rem 1.2rem` for toolbar buttons, `1.2rem 2.8rem` for main search CTAs.
- Hover: `var(--secondary-blue)`, subtle `translateY(-2px)`, blue shadow.
- Focus: blue focus ring via `box-shadow`, not a random outline color.

Secondary/outline buttons:

- Transparent background, `1px solid var(--primary-blue)`, blue text.
- Hover: light blue fill such as `rgba(37, 99, 235, 0.05)`.

Small detail buttons and pagination may use `8px`-`10px` radius, but keep the style consistent inside the same list or table.

### Cards

- Background `var(--card-bg)`.
- Border `1px solid var(--glass-border)`.
- Main radius `var(--card-radius)` (`21px`).
- Shadow `var(--shadow)`.
- Hover: border becomes `var(--primary-blue)`, card rises slightly, shadow increases.
- Big-number cards may use subtle blue radial emphasis, but keep text contrast readable.

Glass registry cards may use `backdrop-filter: blur(16px) saturate(180%)`, translucent surface color, and the same border token. Use glass sparingly where it improves hierarchy.

### Navigation

For portal-like pages:

- Header fixed with a high z-index and `padding: 24px 0`.
- Inner nav is a glass pill: blur around `25px`, translucent background, border `var(--glass-border)`, soft shadow.
- Links use pill hover backgrounds.
- Right side may include language switch `RU/KZ/EN`, theme toggle, and a blue pill login/action button.

For operational dashboards:

- Prefer a compact topbar using the same tokens.
- Keep filters, refresh, export, and theme controls discoverable without making the screen feel like a marketing page.

### Inputs And Filters

- Background `var(--bg-color)` or a subtle translucent surface.
- Border `1px solid var(--glass-border)`.
- Radius `8px`-`12px`; main search can use `var(--pill-radius)`.
- Focus: `border-color: var(--primary-blue)` plus a blue `box-shadow`.
- Checkbox/radio accent: `var(--primary-blue)`.

### Modals

- Overlay: `rgba(0, 0, 0, 0.6)` plus `backdrop-filter: blur(5px)`.
- Content: `var(--card-bg)`, `var(--card-radius)`, `0 20px 40px rgba(0, 0, 0, 0.2)`.

### Category Chips

- Inactive: card surface, subtle border, `8px` radius.
- Active: `var(--primary-blue)` background, white text and icons.

## Layout

- Container: `max-width: 1280px`, horizontal padding `2rem` on desktop.
- Sections: about `40px 0`; dashboard pages can use tighter vertical rhythm when tables need space.
- Grids: `gap: 24px` or `30px`; repeated cards usually `repeat(auto-fit, minmax(280px, 1fr))`.
- Radius scale: `4px`-`6px` for tags, `8px` for chips/details, `12px`-`16px` for icon blocks and small panels, `21px` for main cards, `100px` for pill controls.
- Responsive checkpoints: `1024px`, `992px`, `768px`, `640px`.
- At `768px`, reduce large headings, collapse multi-column dashboards, and ensure all touch targets for critical actions are close to `44px`.

## Prompt Rules For Agents

When the analyst asks for a "beautiful" or "modern" dashboard, translate that into this system:

- Light-first dashboard with complete dark theme.
- Inter typography, blue brand accent, token-based surfaces.
- Pill primary controls and search.
- `21px` main cards with subtle hover elevation.
- Blue focus rings and accessible contrast.
- No random gradients, neon accents, or second brand palette.

Useful prompt snippets:

- "Header/topbar: glass or token-based panel, Inter 800 brand text, compact navigation, theme toggle, primary blue pill action."
- "Dashboard card: `var(--card-bg)`, `var(--card-radius)`, `1px solid var(--glass-border)`, hover border `var(--primary-blue)` and slight lift."
- "Filter chip: active state uses `var(--primary-blue)` and white text; inactive state uses card background and subtle border."
- "Footer: light theme `#f1f5f9`; dark theme `#0a0a0a`; muted text and token-based links."

## Do / Do Not

Do:

- Use CSS variables for every reusable color and surface.
- Keep the primary SDU accent blue across buttons, focus rings, active chips, and chart highlights.
- Support light and dark themes on every new screen.
- Check contrast on glass and blue surfaces.

Do not:

- Use pure black as the light-theme background.
- Mix unrelated card radii inside the same component list.
- Depend on `--accent-yellow` until it is explicitly defined.
